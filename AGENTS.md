## Learned User Preferences

- Use `pnpm` as the package manager (e.g. `pnpm dev`). This is a single-package repo with NO `pnpm-workspace.yaml` (a malformed one previously broke Cloudflare's `pnpm install --frozen-lockfile` with "packages field missing or empty"). Do not commit `package-lock.json`; pnpm is the only lockfile. When adding a dependency, run `pnpm add` so `pnpm-lock.yaml` stays in sync for the frozen install on Cloudflare.
- New shadcn-style React components should be dropped into `src/components/ui/` so the `@/lib/utils` `cn` import resolves.
- Use `lucide-react` for icons when a component needs SVG/logo glyphs.
- Async UI sections should include a loading skeleton and an empty/error state, not just a flash of the empty state.
- Floating-nav / social buttons should have brand-accurate hover colors that work in both light and dark mode (GitHub=black, LinkedIn=#0a66c2, Blog=neon red #ff2d55), implemented via CSS variables + `group-hover:` arbitrary Tailwind classes with `dark:` variants.
- When the user wants to visually check work-in-progress ("preview tab", "check it out"), start `pnpm dev` with `required_permissions: ["all"]` (the sandbox blocks the Cloudflare adapter otherwise) and open `http://localhost:4321/` with the `cursor-ide-browser` MCP tool (`browser_navigate` + `browser_take_screenshot`) rather than doing a full build each time.

## Learned Workspace Facts

- This is an Astro portfolio (`starfolio-1`) using the Cloudflare adapter (`wrangler.jsonc`, worker name `bmoirdevportfolio`); TypeScript + Tailwind + shadcn-style structure. GitHub remote is `bmoir23/starfolio` locally, though GitHub reports the repo has moved to `bmoir23/bmoir-portfolio-app` (pushes still redirect); `master` has branch-protection rules.
- Dev env vars: Cloudflare adapter reads `.dev.vars` locally, Astro/Vite also reads `.env` (`.dev.vars*` is gitignored). In production (`wrangler.jsonc`), non-sensitive runtime vars (`SANITY_PROJECT_ID`, `SANITY_DATASET`, `SANITY_API_VERSION`, `POSTHOG_HOST`) live in the `vars` block so they survive redeploys; secrets (`NEON_DATABASE_URL`, `TURNSTILE_SECRET_KEY`, `POSTHOG_API_KEY`) must be set via the Cloudflare dashboard "Secrets" tab or `wrangler secret put`, never as plaintext vars. `PUBLIC_*` vars are baked in at build time, so git-based Cloudflare Workers Builds also need them under the dashboard's Build environment variables, not just runtime vars.
- Sanity CMS powers the blog + projects: client/queries in `src/lib/sanity.ts`, canonical schemas in `sanity/schemas/` (excluded from `tsconfig.json` so it doesn't break `astro check`). The Studio is a single self-contained package at `sanity/` (project `cv6an3n5`, dataset `portoflio-dev-blog`, own `sanity.config.ts`/`package.json`/lockfile) — don't create a second studio elsewhere. Local env: copy `.env.example` → `.dev.vars`. Seed content: `cd sanity && pnpm seed` (requires `sanity login`) or `SANITY_API_TOKEN=... pnpm seed:sanity` from repo root.
- Blog surface: `src/pages/api/posts.json.ts` (Astro endpoint), `src/pages/blog/index.astro` and `src/pages/blog/[slug].astro` (SSR), `src/components/blog-card.tsx`, `src/components/section/blog-section.tsx`, `src/components/blog-post-body.tsx` (react-markdown + remark-gfm).
- Projects are CMS-driven via Sanity (the old `DATA.projects` array was removed from `src/data/resume.tsx`, now just a comment pointing to Sanity): schema `sanity/schemas/project.ts`, seed `sanity/seed/projects.ndjson`. Surfaces: API `src/pages/api/projects.json.ts`, list `src/pages/projects/index.astro`, detail page `src/pages/projects/[slug].astro`, homepage island `src/components/section/projects-section.tsx`, card `src/components/project-card.tsx` (cards include a GitHub repo link button).
- Contact form (`src/components/contact-form.tsx`, endpoint `src/pages/api/contact.ts`, logic `src/lib/contact.ts`) stores submissions in Neon Postgres and/or forwards to an n8n webhook, and is protected by Cloudflare Turnstile (`src/components/turnstile.tsx`); env vars `NEON_DATABASE_URL`/`DATABASE_URL`, `N8N_CONTACT_WEBHOOK_URL`, `PUBLIC_TURNSTILE_SITE_KEY`/`TURNSTILE_SECRET_KEY`. Setup documented in `CONTACT.md`.
- Analytics stack runs three client-side scripts on every page via `src/layouts/Layout.astro`'s `<head>`: PostHog (`src/components/posthog.astro`), Cloudflare Web Analytics, and Google Analytics gtag.js (inline `is:inline` scripts).
- The AI chat widget is `ChatbotPanel` (`src/components/ChatbotPanel.tsx`), opened via a `Bot` icon button inside the floating navbar dock (`src/components/navbar.tsx`) — not a standalone floating bubble on the page.
- HomePage section order is controlled by the `order` field on each entry in `src/data/resume.tsx`; current order is Hero → githubActivity → about → work → education → skills → projects → blog → contact (photos & hackathons disabled).
- `astro check` reports ~22 pre-existing errors in `src/components/section/hackathons-section.tsx`, `src/components/section/photos-section.tsx`, and `HomePage.tsx:88` (education `start` field), caused by `as const` empty arrays in `resume.tsx`. Do not attribute these to new changes.
- The sandboxed shell cannot run the Cloudflare dev plugin without `required_permissions: ["all"]` (`uv_interface_addresses` error otherwise); prefer `astro check` / build verification when validating in-sandbox without that permission.
